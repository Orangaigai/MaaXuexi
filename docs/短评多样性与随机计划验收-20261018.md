# 短评多样性与随机计划验收

版本：local-20261018.20。修改前 Git 检查点：bb1708c。

## 研究与采用方式

- [Commently 的语气说明](https://commently.mybrowsey.com/docs/tones.html)及此前读取的[生成源码](https://github.com/ankitpro/commently/blob/main/src/utils/llm.ts)将语气与文章上下文分开，支持友好、欣赏、轻松、共情等表达。借鉴的是语气与正文分离的思路，不是照搬24种英文预设或选择成品评论。
- [Replyly](https://github.com/Michonvv/Replyly)提供基于评论内容和个人风格的回复设计；本次核对其公开介绍，没有将其宣传的效率数字当作本项目实测结果。
- 所读[用户讨论](https://www.reddit.com/r/TheoryOfReddit/comments/1fzq991/we_reached_the_point_where_ai_generated_comments/)批评复述内容后泛泛赞同、重复结构、冗长与缺少具体回应；讨论中也有人反对仅凭文风判定AI。它们是主观体验，不是识别率、风控或封号证据。
- 本机自行实现：全文一次生成三条不同角度、句式和情绪的候选，同一次复核逐条判定，仅从合格项中结合最近八条拟发表记录选择较少重复的一条。正常仍为一轮生成、一轮审核，不逐条调用三次或反复重写。历史是负向避重上下文，不是运行话术库，也不提供本篇事实。
- 去除对固定收获短语的正向示范，不再要求每条先复述知识再加感叹。仍允许简短发现、欣赏具体细节、轻松感叹和认可；不把不同文章都写成同一种兴奋语气。
- 候选及审核都使用完整正文。保留8～28字、范围、原文依据、同篇核对、每天发表限制、本人验证及换行识别。多样性不能让未复核的文字进入发布流程，也不能确保模型绝不重复或漏判。

## 随机启动

使用 [Windows 原生 RandomDelay](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger?view=windowsserver2025-ps)：每日07:40为起点，最多随机延迟75分钟，计划在北京时间07:40～08:55内触发一次。保留用户明确选择的StartWhenAvailable，关机/休眠错过后恢复可补跑；补跑可能在窗口之外。

保留原无黑窗启动器、Windows用户、忽略重复实例及运行锁。原任务内部名称MaaXuexi-Daily-0900兼容保留，名称不决定生效时间。页面改读Windows实际触发器，移除过期的静态九点JSON；保存按钮改称每日自动任务清单。

修改脚本会先校验计划动作属于本安装，备份原XML，再修改触发器。安装在当天起点之后时，从次日开始，避免改完即意外补跑今天。手动启动不受这个时段限制。

没有可靠证据能将固定九点等同于封号，也不能证明随机时间降低封号概率。[平台服务协议](https://im-pages.xuexi.cn/agreement/service-agreement/index.html)仍明确禁止借助刷分软件获取积分。随机化不取消该限制，也不自动完成访问验证。
