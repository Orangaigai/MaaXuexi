# 控制台与设置的分工

控制台用于本次执行、进度与结果；设置页用于长期偏好和维护。正常状态减少配置提示，出现需要处理的问题时保留就近入口。

| 内容 | 放在哪里 | 原因 |
| --- | --- | --- |
| 任务选择、保存任务清单、立即执行 | 控制台 | 经常使用，直接决定本次运行 |
| 运行状态、暂停、继续、中止、本人验证提醒 | 控制台 | 执行中需要立即看到和操作 |
| 当前执行方式、下次执行倒计时 | 控制台 | 应一眼知道什么时候启动 |
| 手动/自动切换、时间点/时间段编辑 | 设置 → 执行与定时 | 低频配置；控制台保留“修改设置”入口 |
| 窗口方式、本人处理时显示一次、桌面通知 | 设置 → 窗口与通知 | 长期使用习惯，无需每轮占据首页 |
| 完成后关闭模拟器 / 控制台 | 设置 → 运行收尾 | 长期偏好只保留一处编辑，避免两处开关不同步 |
| 本次保持打开 | 控制台收尾倒计时 | 只改变这一轮，必须就近操作 |
| 每日积分日历与当天结果 | 控制台 | 任务最重要的结果 |
| 历史积分导入 | 首次引导、设置 → 积分记录 | 不常执行，首次仍需可发现 |
| DeepSeek 密钥、验证与教程 | 设置 → 答题服务 | 已配置后不必长期占据首页；缺密钥、余额或连接异常仍在执行处提示 |
| 运行日志 | 控制台底部，默认收起 | 排查“卡在哪里”需要随手可查 |
| 环境自检、版本、使用说明 | 设置 → 帮助与排查 | 属于维护操作；可直接打开控制台日志 |

没有移动任务执行API、修改计划文件格式或更换模型。控制台与定时编辑器共用一套只读时间显示；编辑器继续保留未保存草稿、还原、格式检查和保存失败提示。仅查看设置不会提交任务；保存时恰好在所设时段内立即执行的原有行为仍保留。

## 参考与判断

- [Home Assistant Dashboard 设计说明](https://contributors.home-assistant.io/design/dashboards/) 将首页定义为日常查看状态和控制的地方。这里据此保留运行状态、任务和结果，没有把高频操作全藏进设置。
- [PowerToys 的常规设置与快捷入口](https://learn.microsoft.com/en-us/windows/powertoys/general) 分开处理常规行为与快捷操作；[0.94 更新说明](https://devblogs.microsoft.com/commandline/powertoys-0-94-is-here-settings-search-shortcut-conflict-detection-and-more/) 也体现随着设置增多改善查找的需求。我们的设置项尚少，先用清楚的分组和精准锚点链接。
- [Immich 系统设置](https://docs.immich.app/administration/system-settings/) 将模型、通知、日志等长期配置按用途分组。我们的密钥和环境检查也按用途归入设置，而不是按内部模块名称组织。
- [ntfy 偏好页源码](https://github.com/binwiederhier/ntfy/blob/main/web/src/components/Preferences.jsx) 将通知偏好独立成组；[用户关于设置迁移的反馈](https://github.com/binwiederhier/ntfy/issues/1201) 也提示入口与命名需要让用户知道在改什么。这些反馈是个别案例，不作为普遍使用率或故障率统计。

本次只借鉴信息组织方式，没有引入这些项目的前端框架、复制源码或增加在线依赖。

## 值得后续评估

1. **导出脱敏诊断摘要**：一键取得版本、检查结论和必要运行信息，方便报告问题；先设计明确的脱敏范围，不自动上传。
2. **偏好与任务清单备份**：迁移时复用常用设置，密钥仍在新电脑独立配置；需核对计划归属，避免导入就意外启动。
3. **通知按用途筛选**：例如只提醒需要本人处理和执行异常；现有总开关继续保留。

这些是建议，本次没有顺便加入。当前没有必要增加全站设置搜索或更多嵌套菜单。
