# MuMu 桌面广告与启动衔接修复

版本：local-20261018.18。修改前检查点：952ad03。

## 现场与原因

用户截图是 MuMu 的 Android 桌面广告，实际前台包为 `app.lawnchair`，不是学习强国的访问验证。

旧启动器只启动后台、显示并连接模拟器，不在连接时打开学习强国。因此尚未开始任务时，会留在桌面或桌面广告。旧版任务导航从这个真实广告现场也能打开应用：本次基线实测约 22.2 秒确认首页。不能将截图当作旧任务必然被广告阻断的证据，也不能据此解释此前两天所有停顿。

## 改动

- 手动连接/启动器连接后，读取真实 Android 前台活动。仅确认是 `app.lawnchair` 或 Android Launcher3 桌面时，发送一次学习强国启动命令；不点击广告，也不强制停止后台应用。
- 已有应用、访问验证、登录、系统权限或其他未确认的页面保持原样。读取前台超时也不猜坐标。
- 正式任务准备保留原导航，不在连接阶段额外启动一次。进入积分中心前仍确认竖屏与连续两帧首页。
- 原首页恢复现在检查停止、启动命令的实际结果。命令失败直接报具体原因，不再无条件显示“已打开”后等待两分钟。
- 连接接口将启动失败返回为明确的 503 错误，启动器文字与新行为一致。
