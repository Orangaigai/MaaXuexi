# 读取限制与改进计划

## 历史流水仍依赖视觉读取

当前手机端页面能显示每日积分和流水，但未找到已经接通、可由程序独立复用现有 App 登录的结构化读取通道。当前版本因此采用模拟器翻阅及本机 OCR，API 费用为零。它比原始数据读取慢，也依赖页面布局、字号、截图和滚动效果；这是明确保留的技术限制，不能因一次验收成功就宣称不受页面变化影响。

公开移动 H5 使用原生 LWP 桥发起查询，不是可直接调用的匿名 HTTP API。现用 App 未暴露可用调试通道；[Android 官方文档](https://developer.android.com/develop/ui/views/layout/webapps/debug-chrome-devtools)说明 WebView 调试需由应用启用。PC 官网的查询需要单独登录，不符合当前直接复用模拟器登录的使用要求，未作为必选步骤。

后续优先研究合法、稳定且不额外登录的移动端结构化数据访问。若取得可运行方案，应保留现有导入接口和存储口径，仅替换采集器，并用逐日总分、流水顺序、真实重复记录与零分日期做完整对账。没有验证前不承诺可以取得全部账号历史。

现有视觉方案只保存两遍一致且合计相符的日期，保留真实重复的流水；单日 OCR 不一致会自动重读一次，仍未核实则提示补齐，不对登录、取消或平台验证进行这种重试。时间只能精确到页面显示的分钟。可查询范围由平台决定；不可见的更早记录无法倒推。未来还可评估按日保存进度，减少首次长导入被中断后的重复工作。

## 后续设置入口

已预留历史导入的状态、启动、取消、跳过和按日期读取接口。完整设置页后续加入“设置 → 积分记录”，不在日历工具栏长期放置导入按钮。此前首次提示中的“设置”说明是入口预告，设置页尚未上线；接口用法见[模块说明](architecture.md#历史积分导入接口)。
