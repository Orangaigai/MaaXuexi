# 按全文生成普通读者短评

local-20261018.17 根据账号主人最新要求，将评论目标改为简短、友好、与文章有关的读者反馈。允许感谢讲解、认可具体用处、轻微感叹或简短感想，不强制每条都作独到分析或延伸。

## 实现

- 沿用已接入的 DeepSeek；日常任务将当前文章的完整正文交给模型，不从固定话术库或测试样例挑选句子。
- 移除了生成提示中的成品评论例句，不新增固定句式池、随机话术池或兜底祝福语。
- 每条仍为 8～20 个汉字的一句话，保留原文连续引用依据，再调用模型独立复核。
- 复核将原来强制的 `opinion` 改为 `natural`，允许没有独到见解的贴文感谢或认可；原文依据、相关性、内容范围和反馈对象具体性仍必须通过。
- 只给空泛感谢、夸大效果、虚构亲历或输出不合范围内容仍会停止。模型可能输出相似的常用表达，这不是完全去重承诺。
- 全文读取、文末确认、篇首标题核对、实际页面输入校验、发表后恢复、本人验证与重新核分继续复用原流程。
- 发布范围、次数、选题顺序和已有记录不变；已经点击发布后不会因分数未满而自动换文追加。

## 开源参考

[Commently](https://github.com/ankitpro/commently/blob/main/src/utils/llm.ts) 将语气要求与文章输入分开；[HumanTone](https://github.com/kamrullab/HumanTone) 强调日常词汇、简短回复和用户偏好。本模块参考这些设计思路，自行改写中文生成与复核要求，没有复制其整段提示或接入其发布器。

[LearnChinaHelper](https://github.com/gzhjic/LearnChinaHelper) 使用固定祝福文案，未采用。[Echo](https://github.com/shyamolkonwar/Echo/blob/main/echo/lib/comment_generation.js) 实际源码排除常见夸赞和感谢开场，与本轮需求不同，未照搬其生成规则。

## 验收证据与界限

- 556 项完整离线测试通过，覆盖贴文感谢不需要独到观点、空泛感谢拒绝、原文引用核对和原有全部任务回归。
- 使用同一客户端做三类真实模型调用：1245 字公开生活科普全文、144 字合成植物测试短文、1231 字此前真实读取的医学科普全文；共五次小额请求（两个通过样本各生成与审核两次，未通过样本生成一次）。没有把这些材料加入运行题库或话术库。
- 生活草稿实测：“原来压花能让纸巾不易脱层，挺实用。”；植物草稿实测：“把光照水分温度放一起考虑这点讲得很清楚。”。自然程度仍属于主观判断，小样本不能证明所有文章都能生成合适短评。
- 医学草稿输出超长且涉及病情判断的内容，本地规则已拒绝，未进入发布流程。该结果是拒绝证据，不算医学评论成功。
- 本轮仅做草稿测试，未新增公开评论或积分；此前正式观点已有 1/1。本轮不能冒充新版本从发文到加分的完整验收。
- 上一轮 .16 增加的验证后观点列表恢复识别，已有真实画面判定和离线证据，但整轮无临时辅助的新积分验收仍待下次真实任务。
